# Changelog

User-facing changes to the Postly API, SDKs and CLI. Dates are ISO 8601.

> **Archived 2026-10-07.** Nothing below was ever released: no version was
> published, no SDK went to npm, and no mail was sent to a real recipient. The
> packages stayed at 0.0.1 and the section below stayed "Unreleased". It is kept
> because it is an accurate record of what the code does.

## Unreleased

### Changed

- Every list endpoint pages with a cursor: `?limit=` (1–100, default 25) and `?cursor=`, newest first, and responds `{ data, next_cursor }`. `limit=0` or a non-number now returns 400 instead of 500, and a malformed cursor returns 400 `invalid_cursor`.
- `POST /v1/emails` no longer requires `subject` when `template` is given, and requires one of `html`, `text` or `template`.
- A request body that is not valid JSON returns 400 instead of 500.
- `@postly/node`: the `delete`/`revoke` methods resolve to `undefined` (the API answers 204). They previously threw while parsing the empty body. Every `list` method accepts `{ limit, cursor }`.
- `postly emails` and `postly suppressions` accept `--cursor` and print the next one.

### Added

- Postly delivers its own mail from the EU through KumoMTA; Amazon SES is gone from the sending path.
- Every domain gets its own 2048-bit DKIM key, generated by Postly. `POST /v1/domains` and `GET /v1/domains/:domain` return the records to publish: the DKIM TXT, a return-path MX and SPF, and a recommended DMARC record. The request takes `return_path` (default `bounces`) instead of `region`.
- `POST /v1/domains/:domain/verify` checks DNS for real, pending domains are re-checked every 5 minutes, and `domain.verified` / `domain.verification_failed` webhooks fire on a change.
- Delivery events come from the MTA: `email.delivered`, `email.deferred` (a temporary failure that is being retried), `email.bounced` with `bounce_type` hard or soft, `email.complained` and `email.failed`, each with the SMTP response.

- The API describes itself: an OpenAPI 3.1 document at `GET /v1/openapi.json`, generated from the routes.

- Templates render: a send with `template` gets the version's subject and body with the variables filled in, plus a plain-text part. MJML is compiled when a version is created, and invalid MJML or Handlebars is refused with 400 `invalid_template`.
- `POST /v1/templates/:slug/preview` renders a template without sending.
- `vars_schema` is enforced: variables that do not match return 422 `template_variables_invalid`; an unknown template returns 404.

- `POST /v1/emails/batch`: up to 500 messages, each accepted or rejected on its own, each with an optional `idempotency_key`.
- `DELETE /v1/emails/:id` cancels an email that has not been handed to delivery (typically a scheduled one); `email.canceled` fires.
- `POST /v1/webhooks/:id/replay` redelivers failed deliveries since a time, or specific events.
- `@postly/node`: `emails.sendBatch`, `emails.cancel`, `webhooks.replay`, `templates.preview`. CLI: `postly batch`, `postly cancel`, `postly webhook:replay`, `postly template:preview`.

- Sending limits: the free plan sends up to 100 emails a day and 3,000 a month, and a pay-as-you-go account up to 1,000 a day for its first 14 days; beyond that `POST /v1/emails` returns 422 `quota_exceeded`.
- Accounts whose last 24 hours cross the complaint or hard-bounce thresholds are paused (or, above 0.3% complaints, suspended) automatically. A paused account can still read through the API; sending returns 403 `tenant_paused`.

### Removed

- The `tracking` field on `POST /v1/emails`. Postly does not track opens or clicks.

- `region` on domains, `ses_message_id` on emails, and the `byo_ses` plan.

### Fixed

- Soft bounces no longer suppress the address; only hard bounces and complaints do.
- A send with a template went out with an empty body.
- Two templates created with the same slug at once, or two versions at once, returned 500; now it is 409 for the slug and consecutive version numbers.
- Webhook payloads contain Postly's fields only; the raw provider event is no longer passed through.
- Webhooks cannot be pointed at private or internal addresses; delivery refuses them at connect time.

- An API key could create another key with any scope, including ones it did not hold. A new key can now only have scopes the calling key holds; anything else is 403.
- Path ids that are not UUIDs return 400 instead of 500.
- `DELETE /v1/templates/:slug` answers 204 like every other delete (it returned 200 with a body); `@postly/node` resolves it to `undefined`.
- Webhook URLs must use http or https.

- Two concurrent requests with the same `Idempotency-Key` could send the email twice.
- A send that failed transiently was never retried.
- Webhook deliveries that failed with a network error stayed pending forever, and a lost queue lost them. Both now retry on schedule.

### Fixed

- `@postly/node`: `verifyWebhookSignature` returns `false` for a malformed
  `X-Postly-Signature` header (for example a `v1` value that is not a 64-character
  hex digest) instead of throwing a `RangeError`.

### Changed

- `GET /health` reports on the service's work, not only that it is up: database,
  Redis, the workers' heartbeat, and per queue the backlog, the oldest waiting job
  and the failure streak. It answers `503` when the database, Redis or the workers
  are unavailable.
